# Kuldevta QA console

A one-file web console for exercising Kuldevta Khoj against **stage**: sign in,
run `/kuldevta/identify`, and hold a real conversation with the persona agent.
Built to make multi-turn bugs visible — the kind that a single `curl` cannot
show, because they only appear from the second message onward.

```
python3 app.py            # -> http://localhost:8787, opens your browser
python3 app.py --port 9000 --base https://stage-prabhuji-api.krutyug.ai
```

Nothing to install. Python 3 standard library only.

## Why it is a server and not an HTML file

The api sets `CORS_ALLOWED_ORIGINS` to a fixed allowlist, so a browser page
served from `localhost` (or opened as `file://`) is refused before the request
leaves. This process serves the page **and** forwards `/api/*` from Python,
where CORS does not apply. Nothing about the api is loosened to make it work.

## Security — read before hosting it

Stage runs the **stub otp provider**: the code is always `1234`, and any valid
Indian mobile number logs in. So this console will mint a valid stage JWT for
whatever number somebody types. On a laptop that is a convenience. On a public
URL it is a "log in as any stage user" button.

Three guards, all enforced in code rather than documented and hoped for:

| Guard | Behaviour |
| --- | --- |
| `CONSOLE_PASSWORD` | HTTP Basic. **Required** whenever `PORT` is set — a hosted deploy without it exits at startup rather than serving. |
| Proxy allowlist | Only the endpoints this console uses are forwarded. `/admin/*` and everything else return `403 PROXY_PATH_NOT_ALLOWED`. It is not a tunnel into the api. |
| `API_BASE` | A host matching `prod`/`production` is refused at startup. |

Without `PORT`, the server binds `127.0.0.1` only, so a laptop run is never
reachable from the network.

### Signing in to the console itself

The browser asks once, for the whole tool. **The username is ignored — type
anything.** Only the password is checked, and it is whatever
`CONSOLE_PASSWORD` holds (on Render: dashboard → the service → Environment →
reveal `CONSOLE_PASSWORD`).

That prompt is the console's own front door and has nothing to do with the
phone-number sign-in inside the page. Unlocking the page sets an `HttpOnly`
session cookie, so every request the page makes afterwards — including logging
in with a mobile number — rides on that cookie and never raises the dialog
again. `/api/*` deliberately answers an unauthenticated call with a plain JSON
401 and no `WWW-Authenticate` header, because a browser pops its native
credential box for *any* 401 carrying that header, `fetch()` included.

Proxied endpoints: `/auth/otp/{send,verify,resend}`, `/users/me`,
`/kuldevta/identify`, `/chat/{messages,history}`, `/horoscope/zodiac-signs`.

## Deploying on Render

1. **New → Blueprint**, pick this repo, and Render reads
   `tools/kuldevta-console/render.yaml`.
   By hand instead: **New → Web Service**, Root Directory
   `tools/kuldevta-console`, Runtime Python, Build `true`, Start
   `python3 app.py`, Health check `/healthz`.
2. `CONSOLE_PASSWORD` is generated by Render — copy it from
   **Environment** and share it with whoever needs the console.
3. `API_BASE` defaults to stage. Leave it.
4. `autoDeploy` is **off** on purpose: this is a QA tool, and it should not
   redeploy every time an unrelated api commit lands.

Free plan idles after inactivity, so the first request may take ~30s.

`/healthz` is unauthenticated (Render's probe carries no credentials) and
returns only `{"ok":true,"base":"<api base>"}` — no secrets.

## Using it

**1 · Sign in** — any number, OTP is automatic. Shows the live `chatConfig`:
arm, `agentId`, `show_kuldeveta_chat`, `kuldevtaAssigned`. Numbers that land in
each arm:

| Phone | Arm |
| --- | --- |
| `9900000006` | kuldevta (assigned) |
| `9900000007` | kuldevta (unassigned — expect `409` on send) |
| `9900000008` | content chat |
| `9900000002` | bhagwat gita |
| `9900000003` | control (no chat) |

**2 · Find the kuldevta** — six answers, pre-filled with the Patil/Satara case
that resolves to Khandoba. Renders the deity card as the app would: image,
both names, temple location, tier + `matchedOn`, and the Hinglish reasons.
**Switch deity** swaps in Rathore/Rajput (→ Nagnechi) so you can watch the
persona change inside one conversation.

**3 · Chat** — turns are numbered and **turn 2 is highlighted**, because that
is where identity bugs surface. Errors render inline with their `errorCode`,
and any resolved `content` groups print under the reply (`horoscope: aries`).

### The test that matters

Ask about the **mantra or niyam on the second message**.

RAGFlow substitutes Begin variables into the prompt on the turn they arrive and
never again. Sending them only on the opening turn left the persona without its
own temple, mantra and niyam from turn 2 — and eventually saying *"Main aapka
kuldevta nahi hoon"*. Fixed in #176 by resending the identity every turn; this
console exists so that class of bug cannot hide behind a one-question check
again.
